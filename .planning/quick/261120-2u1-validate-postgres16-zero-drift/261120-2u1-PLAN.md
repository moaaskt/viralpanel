# Quick Plan 261120-2u1: Validação Local de Migrações e Zero Schema Drift em PostgreSQL 16 Descartável

## 1. Contexto e Objetivo

Na auditoria do **Milestone v1.1 — ZUNTO! Visual Engine** ([v1.1-MILESTONE-AUDIT.md](file:///c:/Users/Windows%20Lite%20BR/Documents/GitHub/viralpanel/.planning/v1.1-MILESTONE-AUDIT.md)), todos os requisitos de código foram considerados satisfeitos. No entanto, foi registrada uma **pendência de evidência empírica**:
- O teste `test_postgres_real_migration_and_strict_zero_drift` em `tests/test_migrations.py` foi executado localmente com status `SKIPPED` por proteção *fail-closed* de segurança, devido à ausência de `TEST_DATABASE_URL` e de contêiner PostgreSQL efêmero no ambiente local.
- No GitHub Actions, o workflow `.github/workflows/ci.yml` já contém o serviço `postgres:16`, mas ainda não foi disparado na nuvem devido à regra estrita de zero-commits do repositório local (`git HEAD` em `ab17255`).

**Objetivo desta Quick Task:**
Executar localmente o teste `test_postgres_real_migration_and_strict_zero_drift` contra um contêiner efêmero **PostgreSQL 16** (`postgres:16`) provisionado exclusivamente para este teste com bind local estrito em `127.0.0.1:5433`, comprovando que:
1. As migrações Alembic (`001_initial_schema.py` e `002_add_metadata_json_to_scripts.py`) executam com sucesso (`downgrade base` e `upgrade head`).
2. A detecção de schema drift (`compare_metadata()`) contra o catálogo físico do PostgreSQL 16 retorna exatamente `[]` (zero divergências).
3. Todo o ciclo de vida da infraestrutura efêmera e a auditoria pós-execução de limpeza operam sob proteção estrita `try/catch/finally`, com validação programática de JUnit XML e verificação de integridade operacional de todos os comandos do Docker.

## 2. Requisitos Mandatórios de Segurança & Isolamento

1. **Isolamento de Banco de Dados:**
   - O banco descartável deve se chamar estritamente `viralpanel_test`.
   - É proibido qualquer fallback para `DATABASE_URL` ou configurações de produção/desenvolvimento.
   - Qualquer conexão para banco com nome diferente de `viralpanel_test` deve acionar o bloqueio de segurança `SECURITY BLOCK` do teste.
2. **Isolamento de Rede Local Estrito:**
   - Mapear a porta do contêiner exclusivamente para a interface de loopback local: `-p 127.0.0.1:5433:5432`.
   - O PostgreSQL descartável fica completamente inacessível para qualquer interface de rede externa ou remota.
3. **Autorização Destrutiva Explícita:**
   - Exigir `ALLOW_DESTRUCTIVE_TEST_DATABASE="true"` em tempo de execução no escopo restrito da chamada do pytest.
4. **Ciclo de Vida e Auditoria Totalmente Protegidos (`try/catch/finally`):**
   - Snapshot prévio de volumes (`$volumesBefore = @(docker volume ls -q)` com checagem de `$LASTEXITCODE`).
   - Inicializar variáveis de controle (`$containerStarted = $false`, `$containerId = $null`, `$executionError = $null`, `$cleanupErrors = @()`, `$testPassed = $false`).
   - Entrar no bloco `try` ANTES de qualquer comando Docker.
   - Capturar o ID gerado pelo `docker run` e verificar `$LASTEXITCODE -eq 0` antes de setar `$containerStarted = $true`.
   - Capturar explicitamente `$LASTEXITCODE` após a execução do `pytest.exe` e validar programaticamente o relatório JUnit XML gerado em arquivo temporário fora da árvore do projeto.
   - Exigir estritamente no JUnit XML: `tests=1, failures=0, errors=0, skipped=0`. Qualquer skip ou desvio marca o teste como `FAILED`.
   - Preservar o erro original da execução via bloco `catch`.
   - Executar compulsória e incondicionalmente no `finally`:
     - Limpeza das variáveis de ambiente.
     - Parada e remoção forçada do contêiner.
     - Auditoria completa de limpeza checando `$LASTEXITCODE` de cada comando `docker ps` e `docker volume ls` (nunca assumindo ausência de recursos caso o comando falhe).
     - Verificação de ausência de listeners na porta 5433 em `State Listen` e variáveis limpas.
     - Remoção do relatório JUnit XML temporário fora do repositório após preservação dos dados.
     - Registro explícito e separado do resultado do teste (`testPassed`) e do resultado da limpeza (`cleanupErrors`).
     - Se o teste falhou, manter a Quick Task não aprovada mesmo que a limpeza tenha sido perfeita.
     - Se a limpeza falhou, reportar falha de segurança operacional (`OPERATIONAL SECURITY FAILURE`).
5. **Auditoria Comparativa de Volumes:**
   - Comparar a lista de volumes posterior à execução com `$volumesBefore`, garantindo que nenhum volume órfão tenha sido introduzido pela tarefa (sem presumir ausência de volumes preexistentes no Docker do usuário).
6. **Imutabilidade e Restrição de Código:**
   - A migração `alembic/versions/001_initial_schema.py` permanece intocada (SHA-256 `74E2BA97B1A7FA72F56FEF92CFA97617B82F78EEC71A52F739BAE47744D052EF`).
   - Nenhum arquivo em `src/`, `tests/`, `alembic/` ou `.github/` será modificado.
7. **Governança Git:**
   - Nenhum commit será criado (`git HEAD` permanecerá em `ab17255`).
   - Nenhum push será realizado.
8. **Delimitação de Escopo de Homologação:**
   - Esta validação gera **evidência local independente**.
   - **NÃO homologa** o GitHub Actions (a pendência `POSTGRES-16-CI-EXECUTION` permanece aberta até a execução real do CI na nuvem, sendo anotada no relatório com a referência desta evidência local).

### Tasks 2, 3 & 4: Ciclo Unificado de Provisionamento, Teste, Limpeza e Auditoria
Executar o script PowerShell com validação programática do JUnit XML, auditoria incondicional no `finally` com verificação de exit code e separação estrita de resultados:

```powershell
# 0. Inicialização antecipada de variáveis de caminho e controle
$junitXmlPath = [System.IO.Path]::Combine([System.IO.Path]::GetTempPath(), "viralpanel_pg16_junit_$([System.Guid]::NewGuid().ToString('N')).xml")
$containerStarted = $false
$containerId = $null
$executionError = $null
$cleanupErrors = @()
$testPassed = $false
$junitReportXmlContent = $null

# 1. Snapshot de volumes existentes antes da execução (com checagem estrita de exit code)
$volumesOutput = docker volume ls -q
if ($LASTEXITCODE -ne 0) {
    throw "INITIALIZATION FAILURE: docker volume ls failed with exit code $LASTEXITCODE. Cannot establish baseline volume snapshot."
}
$volumesBefore = if ($volumesOutput) { @($volumesOutput) } else { @() }

try {
    # 2. Provisionamento do contêiner descartável (bind estrito em 127.0.0.1, sem volumes)
    $runOutput = docker run --rm -d --name viralpanel-test-postgres16 `
      -e POSTGRES_USER=postgres `
      -e POSTGRES_PASSWORD=postgres `
      -e POSTGRES_DB=viralpanel_test `
      -p 127.0.0.1:5433:5432 `
      postgres:16

    if ($LASTEXITCODE -ne 0 -or [string]::IsNullOrWhiteSpace($runOutput)) {
        throw "docker run failed with exit code $LASTEXITCODE: $runOutput"
    }

    $containerId = $runOutput.Trim()
    $containerStarted = $true
    Write-Host "Container started with ID: $containerId"

    # 2. Aguardar readiness (pg_isready com loop de timeout defensivo)
    $ready = $false
    for ($i = 0; $i -lt 30; $i++) {
        $res = docker exec viralpanel-test-postgres16 pg_isready -U postgres 2>$null
        if ($res -match "accepting connections") { $ready = $true; break }
        Start-Sleep -Seconds 1
    }
    if (-not $ready) { throw "PostgreSQL 16 failed readiness check within 30s." }

    # 3. Verificação formal de versão do PostgreSQL 16
    $versionOutput = docker exec viralpanel-test-postgres16 psql -U postgres -d viralpanel_test -t -c "SELECT version();"
    Write-Host "PostgreSQL Version: $versionOutput"
    if ($versionOutput -notmatch "PostgreSQL 16") { throw "Runtime version is not PostgreSQL 16.x" }

    # 4. Execução estrita do teste com relatório JUnit XML temporário fora do repositório
    $env:TEST_DATABASE_URL = "postgresql://postgres:postgres@127.0.0.1:5433/viralpanel_test"
    $env:ALLOW_DESTRUCTIVE_TEST_DATABASE = "true"

    & .venv\Scripts\pytest.exe -vv -k "test_postgres_real_migration_and_strict_zero_drift" --junitxml="$junitXmlPath" tests/test_migrations.py
    $pytestExitCode = $LASTEXITCODE

    if ($pytestExitCode -ne 0) {
        throw "PostgreSQL migration test failed with exit code $pytestExitCode"
    }

    # 5. Validação programática do JUnit XML
    if (-not (Test-Path $junitXmlPath)) {
        throw "JUnit XML report was not generated at $junitXmlPath"
    }

    $junitReportXmlContent = Get-Content $junitXmlPath -Raw
    [xml]$parsedXml = $junitReportXmlContent
    $suite = if ($parsedXml.testsuite) { $parsedXml.testsuite } else { $parsedXml.testsuites.testsuite[0] }

    $totalTests = [int]($suite.tests ?? 0)
    $totalFailures = [int]($suite.failures ?? 0)
    $totalErrors = [int]($suite.errors ?? 0)
    $totalSkipped = [int]($suite.skipped ?? 0)

    Write-Host "JUnit Metrics: tests=$totalTests, failures=$totalFailures, errors=$totalErrors, skipped=$totalSkipped"

    if ($totalTests -ne 1 -or $totalFailures -ne 0 -or $totalErrors -ne 0 -or $totalSkipped -ne 0) {
        throw "JUnit validation failed! Expected tests=1, failures=0, errors=0, skipped=0. Received: tests=$totalTests, failures=$totalFailures, errors=$totalErrors, skipped=$totalSkipped"
    }

    $testPassed = $true

} catch {
    # Preservar o erro original da execução
    $executionError = $_
    Write-Error "Execution error caught: $($executionError.Exception.Message)"
} finally {
    # 6. Limpeza compulsória de variáveis de ambiente
    $env:TEST_DATABASE_URL = $null
    $env:ALLOW_DESTRUCTIVE_TEST_DATABASE = $null

    # 7. Descarte forçado do contêiner por ID e nome caso iniciado
    if ($containerStarted) {
        Write-Host "Stopping and removing container $containerId..."
        if ($containerId) { docker stop $containerId 2>$null }
        docker stop viralpanel-test-postgres16 2>$null
        docker rm -f viralpanel-test-postgres16 2>$null
    }

    # 8. Auditoria de Limpeza Incondicional (checando exit code de cada comando Docker)
    # A. Ausência do contêiner criado por ID
    if ($containerId) {
        $remById = docker ps -a --filter "id=$containerId" -q
        if ($LASTEXITCODE -ne 0) {
            $cleanupErrors += "DOCKER AUDIT FAILURE: docker ps (by ID) failed with exit code $LASTEXITCODE. Cannot confirm container absence."
        } elseif ($remById) {
            $cleanupErrors += "Container still exists in Docker by ID: $remById"
        }
    }

    # B. Ausência do contêiner por nome
    $remByName = docker ps -a --filter "name=viralpanel-test-postgres16" -q
    if ($LASTEXITCODE -ne 0) {
        $cleanupErrors += "DOCKER AUDIT FAILURE: docker ps (by Name) failed with exit code $LASTEXITCODE. Cannot confirm container absence."
    } elseif ($remByName) {
        $cleanupErrors += "Container still exists in Docker by Name: $remByName"
    }

    # C. Auditoria comparativa de volumes (detectar apenas novos volumes órfãos)
    $volumesAfter = @(docker volume ls -q)
    if ($LASTEXITCODE -ne 0) {
        $cleanupErrors += "DOCKER AUDIT FAILURE: docker volume ls failed with exit code $LASTEXITCODE. Cannot verify volume state."
    } else {
        $newVolumes = Compare-Object -ReferenceObject $volumesBefore -DifferenceObject $volumesAfter | Where-Object { $_.SideIndicator -eq "=>" }
        if ($newVolumes) {
            $cleanupErrors += "New orphaned volume(s) created during test: $($newVolumes.InputObject -join ', ')"
        }
    }

    # D. Ausência específica de listeners na porta 5433 (State Listen)
    $listener = Get-NetTCPConnection -LocalPort 5433 -State Listen -ErrorAction SilentlyContinue
    if ($listener) {
        $cleanupErrors += "Port 5433 still has active listener(s) in State Listen!"
    }

    # E. Variáveis anuladas na sessão
    if ($env:TEST_DATABASE_URL -ne $null -or $env:ALLOW_DESTRUCTIVE_TEST_DATABASE -ne $null) {
        $cleanupErrors += "Environment variables were not cleared!"
    }

    # F. Remoção segura do arquivo temporário JUnit XML
    if (Test-Path $junitXmlPath) {
        Remove-Item -Path $junitXmlPath -Force -ErrorAction SilentlyContinue
    }

    # 9. Relatório consolidado de desfecho
    Write-Host "`n================ EXECUTION REPORT ================"
    Write-Host "Test execution status: $(if ($testPassed) { 'PASSED' } else { 'FAILED' })"
    if ($executionError) {
        Write-Host "Execution failure detail: $($executionError.Exception.Message)"
    }

    Write-Host "`n================ CLEANUP AUDIT REPORT ================"
    if ($cleanupErrors.Count -eq 0) {
        Write-Host "Cleanup audit status: CLEAN (Proven: all resources released, 0 leaks, Docker state verified)"
    } else {
        Write-Error "OPERATIONAL SECURITY FAILURE: Cleanup audit failed!`n$($cleanupErrors -join "`n")"
    }
    Write-Host "=====================================================`n"

    # Propagação de erro para falha explícita caso o teste ou a limpeza tenham falhado
    if ($executionError) {
        throw $executionError
    }
    if ($cleanupErrors.Count -gt 0) {
        throw "OPERATIONAL SECURITY FAILURE: Cleanup verification failed."
    }
}
```
