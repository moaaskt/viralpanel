  <name>Task 1: Implementar InspectionRunner compartilhado e garantir atomicidade transacional em StudioService</name>
  <files>src/viralpanel/studio/inspection.py, src/viralpanel/studio/service.py, src/viralpanel/cli.py</files>
  <read_first>src/viralpanel/studio/service.py, src/viralpanel/studio/validator.py, src/viralpanel/branding.py</read_first>
  <action>1. Atualizar `src/viralpanel/studio/service.py`:
   - No método `StudioService.produce(db, run_id, script)` envolver a sequência de criação de assets e chamada ao renderer em bloco `try ... except Exception: db.rollback(); raise` para assegurar que falhas durante o render não deixem registros órfãos de `audio` ou `avatar` na tabela `Asset`.
2. Criar `src/viralpanel/studio/inspection.py`:
   - Classe `InspectionRunner`:
     * `clean_inspection_dir(output_dir: Path) -> None`: remove arquivos residuais pré-existentes em `storage/inspection/` (.mp4, .png, .raw, .md) garantindo isolamento total entre execuções.
     * `generate_synthetic_source_video(path: Path, duration: float = 3.0, with_burned_text: bool = True) -> Path`: gera via FFmpeg lavfi um vídeo 1080x1920 com áudio e opcionalmente texto visual na tela (para testar ausência de duplicação de legendas).
     * `run_scenario_normal(db: Session, output_dir: Path) -> dict`: executa o fluxo completo (vídeo base + avatar ZUNTO! + legendas ASS), audita com `MediaQualityValidator`, executa inspeção de pixels de transparência e borda amarela `#FACC15`, e copia os artefatos para `output_dir / "scenario_normal_final.mp4"`.
     * `run_scenario_fallback(db: Session, output_dir: Path) -> dict`: executa o fluxo com áudio puro (fundo lavfi `#0f172a`), audita com `MediaQualityValidator` e copia para `output_dir / "scenario_fallback_final.mp4"`.
     * `generate_inspection_report(results: list[dict], output_file: Path) -> None`: gera o relatório estruturado Markdown com tabela comparativa de métricas técnicas (FFprobe + pixels) e checklist dos 4 critérios visuais como `[PENDENTE DE INSPEÇÃO HUMANA]`.
3. Criar/Atualizar `src/viralpanel/cli.py`:
   - Adicionar subcomando CLI `validate-e2e` que utiliza `InspectionRunner` diretamente, imprimindo resumo no terminal e gerando os arquivos em `storage/inspection/`.</action>

    <automated>python -c "from viralpanel.studio.inspection import InspectionRunner; print('inspection runner imported successfully')"</automated>
    <fails_when>non-zero exit, or output does not contain "inspection runner imported successfully"</fails_when>
  </verify>
  <acceptance_criteria>
    - `InspectionRunner` centraliza a lógica de geração sintética, execução dos cenários, validação e relatório para CLI e testes.
    - `clean_inspection_dir` limpa artefatos antigos antes de gerar novos.
    - `StudioService.produce` possui rollback explícito em caso de exceção.
  </acceptance_criteria>
  <done>Motor unificado de inspeção e atomicidade em StudioService implementados.</done>
</task>
